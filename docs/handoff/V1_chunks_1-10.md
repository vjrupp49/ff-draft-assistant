## Working model established this session

Claude (this chat) does not write code directly. The user executes all code via Claude Code on their own machine. This chat's role: planning, architectural decisions, and writing tightly-scoped prompts for Claude Code, one chunk at a time. After each chunk, Claude Code's report is reviewed here, findings are scrutinized (not just accepted), and the next prompt is written building on verified results. Every chunk ends with Claude Code actually running and empirically testing its work — not just producing code that looks correct.

## Chunk-by-chunk summary

**Chunk 1 — Scaffold + live Sleeper connection.** FastAPI app structure, sleeper.py API client (league/rosters/draft/picks/players, players cached to disk), /api/league-check endpoint proving live connection + roster override side-by-side. WebSocket /ws/draft polls picks every 3s. Verified live against the real league.

**Chunk 2 — Baseline projections + VBD/VORP.** Recency-weighted (3-season) projections from nfl_data_py, scored with real league settings. VBD engine correctly modified for SUPERFLEX (naive VBD assumes 1QB/team; this league needs ~2QB/team demand modeled). Two real bugs found and fixed: (1) QB replacement level was wrong because SUPER_FLEX and FLEX were filled in separate passes, starving QB demand — fixed via combined greedy allocation; (2) Sleeper's own gsis_id field is null for many real active players (e.g. James Cook) — fixed by joining through nfl_data_py.import_ids()'s crosswalk instead. Passed smell test: Allen/Chase/Lamar/Hurts top of board, QBs clearly boosted by SUPERFLEX.

**Chunk 3 — Monte Carlo simulation** (player/roster level only, NOT full season/matchup sim — deliberately scoped out, saved for Phase 2). Log-normal weekly draws moment-matched to projection mean/variance. Same-team players share a correlated shock (TEAM_CORRELATION=0.30). Verified: point estimates reproduce projections; stacked (same-team) rosters show real, monotonically-scaling variance inflation (1.238 for 3/3 same-team pairs, 1.111 for 2/3, ~1.0 for 0/3) vs. a no-correlation baseline — correlation logic confirmed to add real signal, not just be technically present.

**Chunk 4 — MCTS sequential decision engine.** Opponent picks modeled via ADP-proxy (our own VBD ranking, since nfl_data_py has no fantasy ADP endpoint) × positional-need inference — a documented placeholder for the cold-start problem, to be replaced by real learned tendencies in Phase 1.5. draft_state.py supports both hypothetical and real-Sleeper-synced state. Bug found and fixed: raw reward scale (~1000+ pts) made UCB1's exploration term negligible, causing search collapse onto the first-sampled candidate — fixed with reward normalization. After fix: real, explainable disagreement vs. plain VBD (e.g. MCTS moving a scarce RB up ahead of a QB), confirming MCTS adds real sequential-reasoning signal.

**Chunk 4.5 — Stability + adversarial stress test.** Found the #1 recommendation flipped between reruns of an identical scenario. Tested whether more compute fixed it — it didn't; confirmed as a genuine near-statistical-tie, not insufficient sampling. Fix: track standard error per candidate, flag statistical ties honestly (top_pick_statistically_tied_with) instead of presenting false confidence. Second bug found mid-fix: naive variance formula caught catastrophic numerical cancellation at this reward scale — fixed with Welford's stable running variance. Also stress-tested against non-chalk opponent behavior (QB-run, "reach" scenarios) — held up sensibly; notably, MCTS and VBD converge under severe QB scarcity (expected — VBD's own replacement-level math already prices it in there).

**Chunk 5 — Markowitz portfolio risk-adjustment.** Uses the full empirical covariance matrix from Monte Carlo's correlated draws (not re-derived analytically). MCTS's reward function updated to use this risk-adjusted score instead of raw mean points — a real upgrade to an existing component. Verified: a stacked roster with a higher raw mean scored lower risk-adjusted than a diversified roster with similar mean (1291 mean/1247 risk-adj vs. 1278 mean/1258 risk-adj) — correct qualitative signature. Deliberately did NOT build standings-position-aware risk aversion (would need full-league standings simulation — Phase 2). Flagged honestly: the risk penalty mechanism is correctly signed but small for realistic partial stacks (as opposed to extreme full stacks) — this fed directly into Chunk 6's Task 0.

**Chunk 6 — Risk-aversion calibration sweep + Shapley values.** Sweep concluded partial stacks genuinely carry limited absolute risk at this scale — kept default (0.004), avoided over-tuning into a different distortion (very high risk_aversion was shown to bury legitimately good high-mean/high-variance picks). Built Shapley values (Monte Carlo permutation sampling against portfolio.py's risk-adjusted value function, since exact Shapley is computationally infeasible for 15-man rosters). Correctness verified (values sum to roster total value, near-exact). Critical honest finding: the positional-scarcity test — the actual point of building Shapley — FAILED. A similar-value WR joining an already-deep WR group scored about the same as a TE filling a real need. Root cause correctly diagnosed: the value function summed all drafted players' points with no concept of a starting lineup, so it couldn't distinguish a starter from bench depth.

**Chunk 7 — Fixed the Chunk 6 gap: starting-lineup-aware value function.** Reused Chunk 2's already-solved starter-allocation logic (rather than reimplementing) to make portfolio.py's value function lineup-aware: starters get full simulated value, bench gets a discounted fraction (position-varying: QB/RB 0.35, WR 0.20, TE 0.25 at this point — later revised in Chunk 10). Subtle correctness point handled: Shapley must recompute starter/bench status per permutation prefix, not just once for the final roster, since starter status is a property of a subset. Re-ran Chunk 6's exact test: fixed — a TE crossing into a real starting role scored 20+ points higher than a comparable WR staying bench-only (z=5.99, clearly significant). MCTS re-run showed a real, correct emergent effect: QB-heavy rollout paths lost ground because QB can only ever fill 2 league-legal slots.

**Chunk 8 — MCTS re-stress-test + single Draft Score finalized.** Re-verified Chunk 4.5's adversarial scenarios against the twice-updated reward function (risk-adjustment + lineup-awareness) — held up; QB discount confirmed to fire correctly even under artificial QB-run scarcity pressure. Design decision locked in: MCTS's value estimate IS the single Draft Score (the headline number, including honest tie flags). Shapley is NOT a second score to blend in — doing so would violate the project's founding "no weighted averages" principle. Instead Shapley is wired in as a subordinate structured "explanation" (marginal contribution + starter/bench projection) via a new consolidated /api/draft-score endpoint. This connects the full originally-envisioned 8-step pipeline (projections → correlation → Monte Carlo → MCTS → opponent modeling → portfolio optimization → Shapley → single score) end-to-end for the first time.

**Chunk 9 — Full 15-round, 10-team mock draft simulation + outcome validation.** Built a harness running complete simulated drafts with "my" team using each of three strategies (full Draft Score / VBD-only / ADP-only) against identical opponent behavior, across 3 seeds. This is the chunk that answered whether the system is actually worth its complexity, not just whether it runs. Major finding: all rosters, across all three strategies, ended up QB-heavy (5–8 of 15 spots, in a league where only 2 QBs can ever start) — a real, diagnosed calibration bug (the bench discount mechanism fired correctly, but wasn't steep enough given SUPERFLEX's raw QB point inflation). Validation result (despite the QB-glut distortion present in all three): Draft Score beat both baselines in all 3 seeds (avg risk-adjusted score 3339 vs. 3174 [VBD] vs. 3138 [ADP]), and in 2 of 3 seeds won despite a lower raw mean than the runner-up — a direct validation of the risk-adjustment thesis, not just "found higher-scoring players." Also notable: VBD-only actually lost to naive ADP-only in 2 of 3 seeds, showing risk-blind "smart" VBD can be worse than a naive baseline in this format. Confirmed portfolio.py and shapley.py are genuinely general roster-value functions with no draft-specific hardcoding — should extend cleanly to future trade/waiver evaluation.

**Chunk 10 — Fixed the Chunk 9 QB glut, re-validated.** Replaced the flat bench discount with a rank-decaying one (each additional same-position bench player discounted further: discount = BASE × DECAY^(rank-1)). QB BASE lowered to 0.15 with DECAY=0.5 (worked backward from the exact threshold needed); RB checked directly (not assumed fine) and given a milder precautionary decay; WR/TE left unchanged. Re-ran Chunk 9's exact 3-seed harness: QB counts dropped from 8/5/7 to 1/2/2, and Draft Score's win margin over baselines got larger, not just fixed (a former statistical toss-up win of +7.3 became a clear +63.6). Correct 2nd-QB timing (round 9, driven by real SUPERFLEX value) confirmed preserved. One real side effect found and honestly documented, not fixed: MCTS's pre-existing "position-blind greedy rollout continuation" can occasionally undervalue an objectively great immediate pick because of how it continues simulating afterward — flagged as a follow-up for if/when MCTS's rollout policy is revisited, not a blocker.

## Current state — analytical engine

The full pipeline (projections → VBD → correlated Monte Carlo → MCTS with opponent modeling → Markowitz risk-adjustment → lineup-awareness → Shapley → single Draft Score) is built, connected end-to-end via /api/draft-score, and empirically validated via full mock-draft simulation to outperform both a smart baseline (VBD-only) and a naive baseline (ADP-only) across multiple seeds. This is considered the real green light that justified moving to UI work.

## Known open items (not blockers, but tracked)

- risk_aversion (portfolio.py) and BENCH_VALUE_DISCOUNT values are reasoned placeholders, not calibrated against real season data — natural Phase 1.5 candidates once real results exist
- Opponent model is still the Chunk 4 cold-start placeholder (ADP + positional-need proxy) — no real behavioral data on this league's drafters exists yet
- MCTS's "position-blind greedy rollout continuation" edge case (found in Chunk 10) — documented, low severity, not fixed
- No automated test suite — everything verified via manual, thorough, per-chunk testing so far
- No MCTS tree-reuse between consecutive live picks (recomputes from scratch each call)
- Full mock-draft runtime showed a ~25-40% slowdown from round 1 to round 15 (portfolio's covariance computation scaling with roster size) — real, worth monitoring, not yet a hard blocker

## UI phase (handed off to a separate chat)

Backend/analytical work is done; UI design decisions were made at the end of this session and are being executed in a new chat to conserve context. Key decisions already locked in before handoff: this is a glanceable second-screen (user drafts via Sleeper's own app on their phone, watches this tool on their computer) — headline recommended player + big Draft Score number + one-line Shapley-derived "why," options 2–5 shown smaller/secondary, live pick feed with a visible "recalculating for your pick" state, tiered recompute (cheap VBD-based updates after every opponent pick, full expensive Draft Score/MCTS recompute only 1–2 picks before the user's turn). Visual identity intentionally left open for creative, distinctive execution — explicitly not a generic dashboard template.
