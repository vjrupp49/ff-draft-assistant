**Session Summary — ff-draft-assistant, Chunks 11–22 (UI Build + Correctness Hardening)**

*Add this to project knowledge alongside the overview doc and the Chunks 1-10 summary. This chat covered the transition from validated analytical engine to live draft-day UI, followed by a sustained correctness-hardening arc triggered by real live-draft testing. Working model unchanged: Claude Code executes and reports, this chat scrutinizes and writes the next scoped prompt.*

**Chunk 11 — Tiered recompute (superseded)**
Originally scoped as a standalone backend chunk (cheap VBD updates every pick, full MCTS recompute only near the user's turn), but the user ran a combined version instead — see Chunk 12, which covers this ground.

**Chunk 12 — Tiered recompute + full frontend build**
Built the real draft-day UI: dark "broadcast scoreboard" visual identity, headline recommended-player card, secondary options list, live pick feed, "recalculating" state. Backend: `DraftLiveManager` with cheap/expensive tiering (VBD every pick, full MCTS+Shapley only within 1-2 picks of the user's turn). Found and fixed three real bugs via live testing: a silent driver-task death (MCTS required `is_my_turn=True` but the expensive tier fires *before* that — fixed via provisional opponent-pick simulation), a score-display bug (`requestAnimationFrame` throttled on backgrounded tabs), and a reload-always-shows-setup bug. Verified against a full 150-pick mock-draft replay through the real UI (150 cheap / 60 expensive updates, zero errors).

**Chunk 13 — Root-cause: QB shortage / TE glut in MCTS recommendations**
Triggered by a live Sleeper practice draft (Chunk 12→13 handoff) where following the app's recommendations produced QB=1/TE=5 against a league-wide norm of QB=2/TE=2. Root-caused (not patched) to a specific mechanism: MCTS's rollout continuation policy used blind, context-free top-VBD greed, so the model always assumed "I can get a QB later" regardless of the actual root candidate — a self-perpetuating procrastination loop. Fixed with a roster-aware rollout policy (`_roster_aware_pick`) reusing existing, already-proven starter/bench logic. Also fixed a second bug found along the way: no bound on the draft ending, allowing lookahead to simulate fictional rounds 16+.

**Chunk 14 — Stress-test validation of the Chunk 13 fix**
Widened validation from 3 seeds/1 slot to 35 seeds across 3 draft slots, checked for new distortions (none found), and directly tested the draft-end boundary. Self-corrected an earlier runtime claim: original "1.54s mean" was measured too shallow; true cost is ~4.4s mean/8.9s at deeper draft states, ~37% of which is the Chunk 13 fix itself, ~60% pre-existing `opponent_model.py` cost — still comfortably under Sleeper's 60s pick timer, logged as a future optimization target, not fixed here.

**Chunk 15 — First automated regression suite**
Built the project's first pytest suite (previously all validation was manual harness runs). Encodes: positional-balance invariants (multi-seed sweep), slot-sensitivity checks, the draft-end boundary guard, and a fixture-based replay of the real Chunk 12 draft. Found a genuine, previously-unknown bug while building it: `mcts.py`'s reward evaluation had a hardcoded `seed=None`, making every prior "seed=" validation only partially reproducible. Fixed (proper seed threading) and confirmed via 5x byte-identical repeated calls. Re-checked Chunk 13's original claim under corrected determinism — found it had overstated confidence (QB was a genuine near-tie at picks 14/34, not a clean winner); corrected the historical record rather than leaving it standing. Suite verified with a required negative control (fails without the fix).

**Chunk 16 — Audit: is the projection layer forward-looking or historical?**
Pure audit, no fixes. Found the original vision's "Bayesian-blended projections" (FantasyPros + ESPN + ADP + nfl_data_py) was never actually built — only nfl_data_py (backward-looking historical stats) feeds real projections; the other sources were stubbed and left unused. Quantified real consequences: a genuine 2025 first-round rookie RB (Omarion Hampton) buried at rank 597/992 due to zero history; a traded veteran (George Pickens, PIT→DAL) silently projected 100% on stale prior-team data with no flag indicating unreliability — the more dangerous case, since it looks like a normal projection.

**Chunk 17 — Fix: real market ADP integration**
Added FantasyFootballCalculator's free public ADP API (no key required) as a genuine forward-looking signal, after confirming via diagnostic that true SUPERFLEX-format data doesn't exist there (used `2qb` as a documented approximation instead). Built a rank-to-points translation layer and wired it into the projection pipeline for the two confirmed failure modes: rookies (ADP-derived estimate replaces flat fallback) and role-change veterans (new `team_changed` detection + blended estimate). Validated against all 4 traced Chunk 16 players — Hampton moved from rank 597/-146.3 VBD to rank 82/+13.9 VBD. Found and root-caused a real regression during verification (a test assumption about "QB always wins pick 147" went stale as real ADP data changed the ground truth) — redesigned the test around a durable invariant instead of a hardcoded outcome.

**Chunk 18 — Audit + hardening: FFC↔Sleeper name-matching quality**
Full-pool audit (not just the 4 traced players) of the name-based join between FFC and Sleeper data (no shared ID exists). Found zero team mismatches across 188 real matches (strong evidence against silent wrong-player corruption) and 40 fantasy-relevant unmatched players, root-caused to real dataset coverage limits. Hardened with a `ppr`-format fallback lookup (recovered 30 of the 40) and a team-agreement flag as a forward-looking safety net. Found and fixed a serious bug in its own test infrastructure during verification: a new `cache_path` parameter broke test cache-isolation, causing mocked test payloads to silently overwrite the real production ADP cache — caught by not assuming success and rebuilding the real pipeline to check.

**Chunk 19 — Live dry run #2: full-system validation (Chunks 13–18)**
First live test of everything built since Chunk 12's dry run. Confirmed the original Chunk 13 bug is genuinely fixed live (QB never blindly dismissed) and that real ADP data is actively used for real players. But surfaced a new, more severe regression via a different mechanism: final roster QB=1/TE=8 (worse than the original bug). Root-caused live: TE-premium scoring lets elite TEs legitimately win the shared FLEX/SUPER_FLEX slot allocation, pick after pick, with each individual choice a defensible near-tie — but nothing costed "I'm accumulating same-position starters" across the roster as a whole. Diagnostic chunk only, no fix.

**Chunk 20 — Fix: TE/SUPERFLEX flex-slot concentration**
Root-caused with real numbers: league-wide QB and TE replacement levels are nearly tied (147.4 vs 147.7) under this league's actual scoring — the user's "QB should always beat TE" intuition holds at the top of each position but not in the realistic mid-tier zone where the bug lived. Confirmed no mechanism penalized multiple same-position players competing for the same limited flex slots. Built a TE-specific flex-slot concentration discount (rank 1 full value, rank 2+ decays), wired into `portfolio.py`, `shapley.py`, and critically `mcts.py`'s rollout continuation. Self-corrected mid-chunk: an initial generic (all-positions) version of the discount introduced a new WR shortage in harness testing — scoped back to TE-only once evidence showed that was the actual problem, following the same discipline as Chunk 10's original precedent.

**Chunk 21 — Fix: opponent model wired to real market ADP**
Triggered by user-reported reaches and unwarranted deep-sleeper picks. Traced and confirmed: `opponent_model.py` (which MCTS rollouts use to predict "will this player survive to my next pick") was still using the original self-referential VBD-based proxy from Chunk 16, never updated to use the real FFC ADP data added in Chunks 17-18. Quantified the gap against Chunk 19's real 150-pick draft: the VBD-proxy was a median 37 picks off real outcomes; real ADP was 10.5 off, and more accurate 85.7% of the time. Confirmed MCTS's wait-value logic already existed architecturally — the only gap was the opponent model's grounding in reality, not a missing mechanism. Fixed by wiring `opponent_model.py` to the same ADP infrastructure from Chunks 17-18. Post-fix accuracy: top-1 prediction 0.7%→4.4%, median rank-error 40→18.

**Chunk 22 — Live dry run #3 (in progress as of this summary)**
Scoped to validate Chunks 20 and 21 together against fresh live Sleeper infrastructure, with specific attention to a known residual risk: players with no real FFC ADP match (~78% of the pool) still fall back to the less-accurate VBD-proxy for opponent prediction, which disproportionately affects the deep-sleeper-tier players that originally triggered the user's complaint. Prompt sent to Claude Code; report pending.
